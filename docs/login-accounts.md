# ログインアカウントの運用（メールアドレス＋パスワード）

2026-11-17 に、共有アクセスコードによるログインを廃止し、アカウントごとのメールアドレス＋パスワード認証へ移行しました。

## 仕組み

- アカウントは環境変数 `AIO_AUTH_USERS` に JSON 配列で登録します。パスワードそのものは保存せず、scrypt のハッシュだけを保存します。
- `AIO_AUTH_USERS` が未設定・空・不正のときは、誰もログインできません（画面表示:「認証設定に不備があります。管理者に連絡してください。」）。サーバーログには理由だけが出ます（メールアドレスやハッシュは出ません）。
- ログイン状態は最長 14 日です。画面右上の「ログアウト」で終了できます。
- アカウントを配列から削除するか、パスワードを再発行すると、そのアカウントのログイン状態は再デプロイ後の次の操作で無効になります。
- 旧アクセスコード（`/demo-login`、`/api/demo-auth`）と、旧アクセスコードで得たログイン状態は使えません。`/demo-login` を開くとログイン画面へ移動します。
- 全アカウントが同じ記事・生成ログ・WordPress 接続を共有します（アカウントごとの分離はありません）。
- セッション署名の秘密値は従来どおり `DEMO_AUTH_SECRET` です（名前は互換のため据え置き）。

## アカウントを作る

運用者の PC（このリポジトリのクローン）で実行します。どこにも送信・保存しません。

```bash
npm run auth:create-user -- name@example.com
```

Windows では `npm.cmd run auth:create-user -- name@example.com` です。

- 自動生成されたパスワードは、このとき一度だけ表示されます。本人へ、他の人が見られない方法で伝えてください。
- 自分で決めたパスワード（15 文字以上）を使う場合は `--password-stdin` を付け、1 行目を標準入力から渡します。この場合パスワードは表示されません。
- 出力の `{"email":"…","passwordHash":"scrypt:…"}` が 1 アカウント分の項目です。

## Vercel に登録する

1. Vercel の Project `aio-article-generator` → Settings → Environment Variables を開く。
2. `AIO_AUTH_USERS` を Production に追加する（Sensitive を推奨）。値は全アカウントの配列です。
   `[{"email":"a@example.com","passwordHash":"scrypt:…"},{"email":"b@example.com","passwordHash":"scrypt:…"}]`
   Preview で確認する運用なら Preview にも登録します。
3. 再デプロイする（環境変数の変更はデプロイ後に反映されます）。

## 初回の切り替え手順（締め出し防止）

アカウントを登録する前にこの変更をデプロイすると、全員がログインできなくなります。次の順で行います。

1. 顧客と運用チームのアカウントを作る（上記）。
2. Vercel Production に `AIO_AUTH_USERS` を登録する。`DEMO_AUTH_SECRET` は既存のまま使います。
3. この変更を main にマージし、いつもの手順でステージ → 確認 → 昇格する。
4. 読み取り専用スモークを実行する。運用チームのアカウントを `AIO_SMOKE_LOGIN_EMAIL` と `AIO_SMOKE_LOGIN_PASSWORD` に設定し（例: 無視対象の `.env.local`）、`node scripts/production-smoke.mjs`。旧アクセスコードが使えないこと、ログイン、ログアウトも確認します。
5. 顧客へメールアドレスとパスワードを安全な方法で伝える。旧アクセスコードが使えなくなったことも伝える。
6. Vercel から `DEMO_ACCESS_CODE` を削除する（もう読まれません）。

ロールバック: 直前のデプロイを昇格すると、旧アクセスコードのログインに戻ります。その間は、公開リポジトリにある既定コードの問題も戻ります。新しいログイン状態は旧デプロイでは使えず、旧アクセスコードでのログインが必要です。

## 変更・削除

- パスワードの再発行: `npm run auth:create-user -- 同じメールアドレス` で新しい項目を作り、配列内のその人の項目を置き換えて再デプロイします。
- 削除: 配列からその人の項目を消して再デプロイします。最後の 1 件を消すと、誰もログインできなくなります。

## 注意

- パスワードやハッシュを、チャット・Issue・リポジトリに貼らないでください。ハッシュも推測攻撃の材料になります。
- ローカル開発では `.env.local` に `AIO_AUTH_USERS='[…]'` と、シングルクォートで囲んで書きます。
- ログイン試行回数の制限はありません（サーバーレスで共有の保存先がないため）。代わりに、長いパスワード（自動生成は約 116 ビット、手動は 15 文字以上）と、1 回あたり計算コストの高い scrypt で総当たりを防ぎます。

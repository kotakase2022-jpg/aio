# 2026-11-24 相沢様の指摘（WordPressの「投稿先」が表示されない、コラムに下書きがない）への対応

## 指摘の内容

相沢様がWordPress投稿をテストした。手元の手順書には次のように書かれていた。

- ■接続：続けて「投稿先」で「コラム」を選択してください（2回目からは自動で選ばれます）。
- ■保存：3. 管理画面の「コラム」に下書きが入りますので、内容をご確認のうえ公開してください。

これに対し、相沢様からの報告は次のとおり。

- ツールに「投稿先」が表示されない。
- 投稿先を選ばずに「下書き」で「WordPressに投稿」を押しても、WordPressの「コラム」の下書きに記事がない。
- 別の場所に保存されたのか、処理が完了していないのかを知りたい。

添付のGoogle Driveファイルは、このセッションからは開けなかった（ネットワークの許可先外）。

## 原因

- ツールに投稿先（WordPressの投稿タイプ）を選ぶ機能はなく、記事は常に標準の「投稿」（`POST /wp-json/wp/v2/posts`）へ送られていた。
- **記録のうえでは、テスト投稿は完了していなかった。**
  - 11/24 に、本番の投稿記録（`wordpress_posts`）を読み取りだけで確認した（所有者の承認済み）。記録は0件だった。
  - この記録は投稿の直前に作られる予約で、投稿が完了すれば投稿URLとともに残る。WordPressが要求を拒否した場合（4xx）や、カテゴリー・タグの作成、画像のアップロードなど投稿の前段で失敗した場合は、取り消される。
  - 0件ということは、投稿の前段で失敗したか、WordPressが投稿を拒否（4xx）したことになる（投稿先がなかったことに加え、投稿そのものが失敗していた）。
  - ただし、WordPress側は確認していないため、「投稿」に記事があるかは未確認（CodeRabbit の指摘）。WordPressは記事を作成した後にカテゴリー・タグなどを設定するため、その段階で4xxが返ると、記事が残ったまま記録は0件になりうる。投稿先の機能ができる前の送信なので、記事があるとすれば「投稿」の下書き（「コラム」ではない）。
- **失敗に気づきにくかった理由:** 投稿失敗のメッセージは、画面右側の一番上（`active-error`）にだけ表示され、そこまでスクロールもしなかった。「WordPressに投稿」ボタンは同じ欄の一番下にあるため、ボタンの近くには何も表示されなかった。
- **失敗の原因は特定できていない。** 失敗時には記録が残らず、Vercel の実行ログも保存期間を過ぎている。
  - 考えられる原因: WordPressユーザーの権限（カテゴリー・タグの作成や画像のアップロードに必要な権限がない）、Application Password の誤り、セキュリティプラグインによる REST API の制限、通信の失敗など。
  - 画面に表示されたメッセージがわかれば絞り込める。相沢様の共有ファイルに写っている可能性がある。
- 記事そのもの: 投稿が失敗しても記事の状態は変わらないため、「承認済み」のまま残っているはず（本番データでは未確認）。投稿予約も残っていないので、送り直しにデータの変更は不要で、「コラム」を選んで投稿し直せる。
  - 投稿し直す前に、WordPressの「投稿」の下書きにテストの記事がないかを確認してもらう。あった場合は、「コラム」への投稿と重複しないよう、相沢様の判断で整理してもらう。
- このリポジトリのどのブランチ・履歴にも「投稿先」の実装はない。手順書の記載が、ツールにない機能を前提にしていた。手順書の出所は、このリポジトリの外。
- 付随して、投稿時には記事のカテゴリー・タグが、WordPressの「投稿」用カテゴリー・タグとして（なければ新規に）作られる。テスト投稿でも作られた可能性がある。

## 対応（PR #58、PR #59）

- 投稿先一覧の取得: `POST /api/wordpress/post-types`。
  - 接続したユーザーが作成できる投稿タイプを、`/wp-json/wp/v2/types?context=edit` から読む。
  - 固定ページ・WordPress内部の型・管理画面に出ない型は除外する。
  - タイトルと本文（editor）の両方を保存できない型も除外する。本文が保存されないまま「投稿済み」になるのを防ぐため（CodeRabbit の指摘）。
  - 対応項目（`supports`）が報告されないカスタム型も、本文を保存できるか確かめられないため除外する（PR #59、CodeRabbit の再指摘）。「投稿」は従来どおり。
- 画面（「WordPress投稿」欄）:
  - 「保存」（接続）の後に「投稿先」を表示する。
  - そのサイトで初めて投稿するときは、必ず選んでもらう。一覧が「投稿」だけでも自動では選ばず、気づかずに「投稿」へ入るのを防ぐ。選ぶまで「WordPressに投稿」は押せない。
  - 選んだ投稿先は、サイトごとにこのブラウザへ記憶し、次回は自動で選ぶ（手順書の「2回目からは自動で選ばれます」）。別のパソコンやブラウザでは、初回にもう一度選ぶ。
  - 一覧にない投稿先は、WordPress側でREST APIに公開されていないか、接続したユーザーにその投稿先の編集権限がない可能性がある、と画面に表示する。
  - 一覧を読めないときは、エラーと「再読み込み」を表示する。その間は「投稿」だけを、明示的に選んだ場合に限って使える。
  - 完了メッセージに「投稿先：コラム」のように投稿先を表示する。
- 投稿:
  - サーバーが投稿タイプをサイトから読み直し、その型のRESTルートへ投稿する。ブラウザから送られたルートは使わない。
  - 投稿予約（二重投稿防止）より前に投稿先を確定する。存在しない投稿先や読めない場合は、何も予約・作成しない。
  - 投稿先が対応していないカテゴリー・タグ・アイキャッチ画像・抜粋は送らない。ターム作成や画像アップロードもしない。送らなかった項目は、警告で知らせる。
  - 投稿先の指定がない古い画面からの投稿と、「投稿」を選んだ場合は、従来どおり。
- 投稿失敗の表示（PR #59）: WordPress投稿の失敗・結果不明のメッセージを、画面上部ではなく「WordPressに投稿」ボタンのすぐ下に表示する（`role="alert"`）。WordPress欄の入力を変えると消える。
  - 投稿の結果（失敗・完了）は、その記事を表示しているときだけ表示する。生成ログから別の記事を開いても、前の記事の結果は出ない（CodeRabbit の指摘）。
  - 画面の下端で投稿したときは、結果が見える位置まで、必要なぶんだけスクロールする（CodeRabbit の指摘）。

## 未確認事項・残課題

- テスト投稿が失敗した原因。画面に出ていたメッセージ（相沢様の共有ファイルに写っている可能性がある）がわかれば絞り込める。
- WordPressの「投稿」の下書きに、テストの記事が残っていないか。WordPress側は確認していない。記録が0件でも、記事が作成された後に4xxが返った場合は残りうる（CodeRabbit の指摘）。返信文で確認をお願いしている。
- テストの記事が「承認済み」のまま残っていること（本番データでは未確認）。承認済みでなければ、生成ログから開いて「承認済みに変更」してから投稿する。
- 相沢様のサイトで「コラム」が一覧に出るかは未確認。
  - 表示されない場合は、まず「投稿先」欄のエラー表示の有無を確認する。
  - 次に、接続したユーザーの権限（コラムを編集できるか）を確認する。
  - そのうえで、サイト管理者にREST API公開（`show_in_rest`）の設定を確認してもらう。
- 投稿の前段でカテゴリー・タグが作られてから失敗した場合、WordPressに未使用のカテゴリー・タグが残っている可能性がある（未確認）。
  - ツールは同じ名前のカテゴリー・タグがあればそれを使い、新しくは作らない。そのため、見覚えがなくてもほかの記事で使われている場合がある。削除は、使用状況を確かめてからにする（CodeRabbit の指摘）。
- 本番でのログイン後の画面確認は、アクセスコードの変更により、このセッションからは行えない（所有者または相沢様の確認が必要）。

■ 対応
次の2点を改善いたしました。
1. 投稿先を選べるようにしました。
 (1) 「WordPress投稿」欄で、サイトURL・ユーザー名・Application Passwordを入力し、「保存」を押してください。
 (2) 「投稿先」に、WordPressで使える投稿先が表示されますので、「コラム」を選択してください。
 (3) 「下書き」を選んで「WordPressに投稿」を押すと、「WordPressへ下書き投稿しました。 投稿先：コラム」と表示されます。管理画面の「コラム」に下書きが入りますので、内容をご確認のうえ公開してください。

2. 投稿に失敗した場合は、「WordPressに投稿」ボタンのすぐ下に、赤い枠で理由を表示するようにしました。

■ お願い
投稿し直す前に、念のため、WordPress管理画面の「投稿」の下書きに、テストの記事が入っていないかをご確認ください。投稿先を選べるようになる前のテストでしたので、入っているとすれば「コラム」ではなく「投稿」です。入っていた場合は、「コラム」へ投稿し直すと同じ記事が2件になりますので、不要な方を整理していただけますと幸いです。
テストの記事は、生成ログから開いて「コラム」を選び、そのまま投稿していただけます（「承認済み」になっていない場合は、「承認済みに変更」を押してから投稿してください）。

■ 「コラム」が表示されない場合
「投稿先」に「コラム」が表示されない場合は、ツールに登録したWordPressのユーザーに「コラム」を編集する権限がないか、WordPress側で「コラム」が外部連携（REST API）に公開されていない可能性がございます。その際はお知らせください。確認していただく点と、サイトの管理者（制作会社さま）へのご依頼内容をご案内いたします。

・テストの際、記事のカテゴリー・タグだけがWordPressに作られている場合がございます。ただし、見覚えのないカテゴリー・タグでも、ほかの記事で使われている場合がございますので、削除はなさらずにご連絡ください。
